## 1. 任务执行顺序与依赖图谱

10 项任务划分为三个阶段：第一阶段各任务无交叉依赖，负责奠定系统基石；第二阶段攻坚书架主屏与文件目录浏览；第三阶段聚焦阅读器核心体验与排版渲染。

## 2. 详细任务卡片

### UX-01 — 系统视口避位与全局脚手架（Scaffolding）

- **目标组件**：`MainActivity.kt`、`AndroidManifest.xml`、`LeafletNav.kt`、`Theme.kt`。
- **问题现状**：调用 `enableEdgeToEdge()` 后，系统时钟、电池与前置摄像头直接遮挡在 `Library`、`Settings`、`Reader` 顶部标题文字上方（ISS-001、ISS-002）。应用无法作为系统“打开方式”关联 `.md` 与 `.txt`（ISS-003）。
- **具体改造**：
  1. 使用标准 `Scaffold` 包裹顶层导航界面，或在所有顶层界面容器上显式应用 `Modifier.windowInsetsPadding(WindowInsets.safeDrawing)`。
  2. 确保底部手势横条或导航栏不遮挡底部的设置、关于按钮及阅读进度文字（`1 / 9 · 0%`）。
  3. 在 `AndroidManifest.xml` 中为 `MainActivity` 增加 `<intent-filter>`，支持 `text/markdown`、`text/plain` 以及 file/content 类型的 `ACTION_VIEW`。
- **验收标准**：
  - 在 Android 15 模拟器上，状态栏时间与图标与应用标题、按钮绝不重叠。
  - 底部系统手势指示条不遮挡阅读底栏文字。
  - 在系统文件管理器中点击 Markdown 文件，“打开方式”列表中包含 Leaflet。
- **停工条件**：在横屏和竖屏模式下完成真机模拟器核验，无任何视觉重叠。

### UX-02 — 墨水屏色彩令牌与高对比度搜索高亮

- **目标组件**：`Theme.kt`、`EntryBindings.kt`、`ReaderScreen.kt`。
- **问题现状**：搜索高亮使用饱和度极高的亮黄色 `#FFFF00`，在 16 阶灰度墨水屏上泛白至几乎不可见（ISS-004）。`LeafletTheme` 中未指定的 Material 3 令牌在单色模式下退化为浅紫色（ISS-005）。
- **具体改造**：
  1. 补齐 `Theme.kt` 中的 `DisplayMode.EINK` 颜色方案：显式指定 `surfaceVariant = Color(0xFFF4F4F4)`、`onSurfaceVariant = Color.Black`、`outline = Color.Black`、`outlineVariant = Color(0xFFCCCCCC)`、`secondary = Color(0xFF555555)`。
  2. 更新 `EntryBindings.annotated` 与 `applyStaticSpans`：
     - 墨水屏模式：未选中的搜索命中词使用清晰的 `#CCCCCC`（30% 灰阶底色）或线框勾勒；当前命中词使用高对比反色纯黑底白字（`#000000` / `#FFFFFF`）。
     - 标准模式：采用自适应当前主题的清晰无障碍高对比色彩。
- **验收标准**：
  - 墨水屏模式下，在 16 阶灰度屏上所有非当前搜索结果均清晰可见且易于辨识。
  - 墨水屏模式下所有 Material 3 组件均无任何淡紫色或紫粉色残留。
- **停工条件**：通过 `chineseFiveMatchesAcrossBlocks` 单元测试并在模拟器上完成目视核验。

### UX-03 — 选项控件规范化与排版实时预览卡片

- **目标组件**：`LeafletNav.kt`（`SettingsScreen`、`DisplayModeButton`、`StepRow`、`FontFamilyRow`）。
- **问题现状**：模式与字体切换采用巨大实心按钮与单薄文本按钮的奇怪搭配（ISS-007）。步进器显示生硬的 `"Step 2 of 3"` 且无即时反馈。修改排版必须退出设置打开文档才能看到效果。
- **具体改造**：
  1. 将单选与开关规范化为 Material 3 `SingleChoiceSegmentedButtonRow` 或带统一边框的选项卡（Outlined Chip）。
  2. 步进器增加真实单位标注（如 `"16 sp"`、`"1.4×"`、`"24 dp"`），替代含义不明的 Step 数字。
  3. 在 `SettingsScreen` 排版分区顶端增加一块“排版实时预览卡片”，内置一段样本文本；字号、字体、行距或页边距变动时，卡片内文本毫秒级实时重排呈现。
- **验收标准**：
  - 设置界面控件具有统一的视觉重心与对齐规范。
  - 预览卡片无需退出界面即可实时呈现字体大小、衬线/非衬线、行高与边距的视觉变化。
- **停工条件**：单元测试与页面测试全绿，设置项持久化存储读写完全正常。

### UX-04 — 书架与最近阅读整合及进度展示

- **目标组件**：`LibraryScreens.kt`（`LibraryListScreen`）、`RecentSection.kt`、`RecentViewModel.kt`。
- **问题现状**：未设权重的 `LazyColumn` 嵌套在不可滚动的容器内，条目增多时将最近阅读与底部设置按钮挤出屏幕（ISS-008）。最近阅读使用普通的 `for` 循环（ISS-009）。条目缺乏图标与阅读百分比（ISS-010、ISS-011）。
- **具体改造**：
  1. 将 `LibraryListScreen` 重构为单一完整的 `LazyColumn`，由四个部分构成：
     - 顶部操作头（标题与添加文件夹按钮）。
     - “书架目录”分组头，每个书架卡片带文件夹图标与文件数量。
     - “最近阅读”分组头，每个记录带文档图标、标题、所属目录、相对时间和醒目的阅读进度标签（如 `35%`）。
     - 底部“设置”与“关于”快速导航项。
  2. 将失效/丢失文件的提示精简为内联微标（如 `"文件已移出 [移除]"`），替代冗长的整段文字解释。
  3. 所有列表可点击行的最小高度确保不低于 48 dp。
- **验收标准**：
  - 拥有 10+ 个书架目录或 20+ 个最近阅读条目时，整个页面可顺畅统一滚动，无任何内容截断。
  - 最近阅读卡片清晰显示上一次阅读的百分比进度。
  - 交互列表项完全满足 48 dp 触控规范。
- **停工条件**：在 0 个、1 个、5 个、20 个目录与最近条目场景下完成界面核验。

### UX-05 — 目录面包屑导航与 48dp 触控热区

- **目标组件**：`LibraryScreens.kt`（`LibraryBrowseScreen`）、`LibraryViewModel.kt`。
- **问题现状**：深度子目录缺乏面包屑（ISS-014）。扫描进度提示插入导致下方列表垂直跳动（ISS-015）。文件列表行垂直内边距过紧（ISS-016）。文件夹与文件仅靠末尾斜杠区分（ISS-017）。
- **具体改造**：
  1. 在 `LibraryBrowseScreen` 顶部增加可交互的面包屑路径条（例如 `资料库 > 文档 > 笔记`），读者点击任一父级分段即可快速跳转。
  2. 为扫描进度文字与按钮预留固定高度槽位，彻底消除扫描状态触发时的列表位置垂直抖动。
  3. 增加文件列表项的垂直 padding，保证每行点击区域高度不低于 48 dp。
  4. 列表项前置文件夹图标与文档类型徽章（区分 `.md` 与 `.txt`）。
- **验收标准**：
  - 点击面包屑中的父级分段能正确退出子目录并刷新到目标层级。
  - 开始或取消扫描时，下方文件列表绝对不发生上下跳跃。
  - 所有文件条目的触控高度不低于 48 dp。
- **停工条件**：在三层及以上深度的文件夹结构中测试通过。

**状态（2026-10-01）：DELIVERED — 软件已验证，设备待补。** 浏览切片已按 NB-00–NB-05 实现：带校验的面包屑、不再移动文件列表的保留扫描状态区域，以及带文件夹/文档类型提示的 ≥48 dp 行。`test --rerun-tasks`（820 个用例）与 `lint` 通过，两个 debug 发行版本均可构建；无设备时页面回归为 NOT_RUN，UX-01/UX-02/UX-04 仍未交付并附有明确记录的依赖收窄。见 [library-navigation-ux-delivery.zh.md](library-navigation-ux-delivery.zh.md)。

### UX-06 — 零重排阅读器浮层化工具栏架构

- **目标组件**：`ReaderScreen.kt`（`ReaderContent`、`ReaderScreen`）。
- **问题现状**：将标题、搜索栏与底部菜单作为流式子项放置，每次菜单显隐均会导致正文 `LazyColumn` 尺寸缩放，引发全篇重排与墨水屏剧烈残影闪烁（ISS-018、ISS-019）。触控区缺乏新用户引导（ISS-020）。
- **具体改造**：
  1. 重构 `ReaderContent` 视口布局：
     - 正文 `LazyColumn` 占满屏幕全尺寸（`Modifier.fillMaxSize()`），视口尺寸恒定不变。
     - 文档标题收纳为正文首页的自然标题或轻量浮动顶栏，禁止常驻挤占 64 dp 的正文空间。
     - 阅读菜单与搜索栏移入独立**绝对浮层（Overlay）**，悬浮于正文之上。菜单弹出/隐藏仅改变浮层可见性，正文 `LazyColumn` 的几何尺寸维持恒定不变。
  2. 首次进入阅读器时展示轻量的不透明触控引导图层，标注上一页（左 33%）、呼出菜单（中 34%）、下一页（右 33%），带“知道了”一键关闭。
  3. 底部阅读进度整理为贴底的优雅阅读状态行。
- **验收标准**：
  - 呼出或收起菜单、打开搜索栏时，正文 `LazyColumn` 的高度与宽度绝对不发生改变，正文文本完全不产生重排。
  - 在墨水屏模拟器上，呼出菜单不触发正文区域波形刷新闪烁。
  - 触控引导仅首次启动展示一次，关闭后持久记录。
- **停工条件**：通过 Android 布局检查器与模拟器走查确认零尺寸重排。

**状态（2026-09-30）：已交付，设备证据待补。** 列表几何尺寸已冻结，所有外层控件均为浮层，翻页按实测可见高度计算，标题为瞬时显示，首次运行触控区提示已持久化。`test lint ktlintCheck` 与双变体 debug 构建均通过；新增插桩验收测试可以编译，但未运行（本机无设备/模拟器）。见 [ux-06-delivery.md](ux-06-delivery.md)。

### UX-07 — 表格多行全局对齐网格与图片自然缩放约束

- **目标组件**：`ReaderScreen.kt`（`TableBlockEntry`、`ImageEntry`、`CodeBlockEntry`）、`TableGrid.kt`、`ImageDimensions.kt`。
- **问题现状**：表格每行独立计算列宽导致列错位，表头文本挤压粘连（ISS-023）。16×16 px 的小图标被强制拉满全屏至 1080 px（ISS-024）。代码块复制后提示文字永久常驻不退（ISS-025）。
- **具体改造**：
  1. 在 `TableBlockEntry` 中：
     - 预先遍历表格所有行，计算各列的全局最大列宽。
     - 按照同步列宽渲染各单元格，保证第 $i$ 列在所有行中的宽度完全相等。
     - 增加 1 dp 的单元格边框细线与表头下方的 2 dp 分隔线。
  2. 在 `ImageEntry` 中：
     - 移除位图上无条件的 `fillMaxWidth()`。
     - 保留占满宽度的解码容器，只为位图设置根据设备密度换算的明确尺寸。图片居中且不放大，按视口宽度及 320 dp 高度等比例限制，保留长图和全景图的宽高比。
  3. 在 `CodeBlockEntry` 中：
     - 将反馈显示在现有复制操作内，自最近一次点击 2000 ms 后将 `copied = false`。连续点击重新计时；反馈不插入新行、不移动文档。
- **验收标准**：
  - Markdown 表格列在多行间实现精准垂直对齐，表头与内容单元格有清晰网格分界。
  - 小尺寸图片（如 16×16 px 图标）居中显示且不发生满屏拉伸放大。
  - “代码已复制”提示自最近一次点击 2 秒后恢复为“复制代码”，不移动代码或后续内容。
- **停工条件**：通过 `tables.md` 与 `relative-images.md` 样本测试。

**状态（2026-09-30）：IMPLEMENTED — 软件验证通过，硬件待验证。** 已交付带样式内容统一列宽与网格分隔线、按密度换算且居中的受限图片，以及两秒复制反馈。全部 JVM、静态门禁和两个调试构建通过；两种发行版各通过 57 项页面用例，并在并行目录调整后各追加 9 项复验。六项新页面用例在旧渲染实现上均失败。见 [ux-07-delivery.md](ux-07-delivery.md)。

### UX-08 — 正文段落内行内超链接原生渲染

- **目标组件**：`ReaderScreen.kt`（`ParagraphEntry`）、`MarkdownRenderer.kt`。
- **问题现状**：`ParagraphEntry` 将 Markdown 链接剥离后以全宽大按钮堆叠在段落末尾，严重割裂阅读排版（ISS-021）。
- **具体改造**：
  1. 使用 Compose 的 `AnnotatedString` 结合下划线样式，在段落正文中将链接行内显示。
  2. 墨水屏模式下显示细下划线，标准模式下显示主题色高亮下划线。
  3. 点击行内链接直接触发 `onLinkTap`，且手势不传递至翻页触控区。
- **验收标准**：
  - 链接完美嵌入在正文段落中显示，段落末尾不再出现堆叠的大按钮。
  - 点击行内链接能够准确触发文档跳转或调用外部应用打开。
- **停工条件**：在包含多链接的真实段落样本中验证通过。

### UX-09 — 模态章节大纲抽屉与紧凑型搜索栏

- **目标组件**：`ReaderScreen.kt`（`TocDrawer`、`SearchBar`）。
- **问题现状**：打开大纲直接将正文卸载并替换为单调列表（ISS-027）。大纲标题缺乏级别标识与定位信息（ISS-028）。搜索栏占用两行空间，软键盘弹起后遮挡四分之三的正文（ISS-029）。
- **具体改造**：
  1. 将 `TocDrawer` 改为从侧边滑入的模态抽屉（Modal Drawer）或带遮罩层的浮动侧边栏，正文保持常驻。
  2. 目录项增加 `H1`、`H2` 标签并突出显示当前章节，带有章节进度信息。
  3. 将 `SearchBar` 整合为紧凑的单行工具条：搜索输入框、匹配计数（如 `3/12`）、上一个/下一个图标按钮及关闭按钮集中在同一行。
  4. 增加大小写敏感切换按钮（`Aa`）。
- **验收标准**：
  - 打开大纲抽屉不卸载正文；点击遮罩层可直接关闭抽屉。
  - 搜索栏压缩为紧凑单行，软键盘唤起时仍保留充足的正文阅读区域。
- **停工条件**：在包含 50+ 章节的大型文档中验证通过。
