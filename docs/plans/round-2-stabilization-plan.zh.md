# 下一轮 — MVP 缺陷收敛

[English](round-2-stabilization-plan.md) | 中文

状态：READY FOR ASSIGNMENT（计划可派发，不表示代码已修复）
依据：[2026-09-18 验收报告](acceptance-2026-09-18.md)

## 目标与停止条件

修复 F01–F08 中阻塞基础阅读、数据一致性和有效验收的问题，形成可以在真实 App 页面验证的 M1 Alpha 候选。保持现有技术栈和双 flavor，不新增 M2 功能、不引入厂商 SDK、不开展大范围重构。

每个任务先添加能复现问题的针对性回归，再做最小修复。必须验证**生产路径**；仅断言模型枚举、源字符串或 helper 返回值不构成 UI 功能验收。

REQ 已存在，不另建重复产品需求；修复任务沿用对应 REQ 并更新实际实施状态。状态与证据由 R2-08 最终汇总，不提前标 DONE。

## 顺序与依赖

推荐执行顺序：

```text
R2-00 构建基线
  → R2-01 解析/读取边界
  → R2-02 分块和位置映射
  → R2-03 真实渲染和图片
  → R2-04 存储提交一致性
  → R2-05 阅读状态和错误恢复
  → R2-06 搜索闭环
  → R2-07 页面级验收
  → R2-08 文档和发布候选复核
```

这是保守的单 agent 顺序，不要求并行。若用户另行安排多个 agent，R2-04 可以在 R2-00 后独立进行；R2-01/02/03/05/06 共享 Reader 契约，默认串行。全局 Gradle 与版本目录只由 R2-00 修改，其他任务确需测试依赖时集中协调，避免交叉覆盖。

## R2-00 — 可复现构建与有效门禁

- 优先级：P1；前置：无；对应 REQ-0011，发现 F08。
- 文件范围：`gradle.properties`、Gradle 配置、CI、build/testing 文档。
- 实施：移除仓库内机器专属 JDK 路径，通过环境/本地用户配置使用 JDK 17；保持当前版本不升级。确认 SDK 配置不依赖宿主 init 脚本。明确格式检查覆盖所有源码模块，修复因此暴露的格式问题仅作为本任务必要机械变更。
- 验收：macOS 和干净 Linux JDK 17 环境可执行双 debug 构建、单测、lint、格式检查；记录实际环境与任务结果。无法取得 Linux 环境时明确未验证，不声称 CI 通过。
- 测试基线：记录 test count；为后续 app UI 测试配置 runner/依赖，允许先无用例，但文档必须明确“尚无页面测试”。
- 停止：只修构建/门禁，不顺带升级 AGP/Kotlin/Compose，也不自动推送或建立远端仓库。

## R2-01 — 生产解析线程、读取/缓存边界与损坏编码

- 优先级：P0；前置：R2-00；对应 REQ-0002、0003、0011，发现 F02/F07。
- 文件范围：ReaderSession、TextPipeline、必要的 parser 接口与回归测试；ViewModel 只改必要注入点。
- 实施：将 decode/parse 的 CPU 工作明确放在后台 dispatcher；流读取在 IO，取消可关闭/终止读取。先设计有界读取和降级策略，再读取数据，禁止 readBytes 后截取冒充内存上界。使用标准字符解码能力处理损坏 UTF-8。缓存明确容量/淘汰，未知指纹不命中。
- 验收：通过实际 ReaderSession/生产 scope 验证 dispatcher；100 KB/1 MB/5 MB/10 MB 多块和巨大块无 UI 阻塞，取消目标沿用 REQ 的 1s；慢流取消释放资源。对大于阈值文件提供明确可继续阅读的降级/分段行为，不能静默丢尾部。
- 回归：非法 UTF-8（含 F4 90 80 80、过长编码、代理区、截断字节）、null 指纹重开、多文件切换缓存上限、旧解析迟到。
- 停止：不开发完整分页引擎或通用流处理框架；若同步解析器无法满足取消边界，提交有依据的局部降级方案，不靠扩大测试 timeout 结案。

## R2-02 — 源内容完整性与唯一位置映射

- 优先级：P0；前置：R2-01；对应 REQ-0002、0006、0008、0009，发现 F03。
- 文件范围：MarkdownRenderer/BlockSlicer、DocumentParser、位置模型、TocNavigation 与相关测试。
- 实施：取消用可见文本 contains 猜测块源范围的主路径，采用能保留全部内容和结构的解析产物/映射；超长块必须完整分段。一次建立唯一 anchor → block 映射，TOC、链接、位置恢复共用，不叠加 workaround。
- 回归输入：连续无空行标题、同名标题、标题互为子串、`# A **B**`、引用/列表内标题、反引号和波浪线代码围栏、含空行且超过 4000 行的单代码块、超长表格、文档末尾唯一标记。
- 验收：正文不存在遗漏/重复；末尾标记可见可搜；同名 TOC 指向不同正确块；带行内格式的标题可跳转。1000+ 标题映射无按标题逐次全文查找，记录规模翻倍的实测趋势。
- 决策边界：优先复用现有解析器 AST；若确需修改解析器依赖，先更新 ADR 和兼容/体积证据，不直接替换整套框架。
- 停止：形成一个生产可用映射，不新增平行定位体系。

## R2-03 — 接通真实 Markdown 与本地图片显示

- 优先级：P0；前置：R2-02；对应 REQ-0002、0007、0009，发现 F01/F04。
- 文件范围：ReaderScreen、ReaderHostView/渲染适配、图片生命周期、必要的页面测试。
- 实施：在现有 LazyColumn 内接入原生富文本视图，或使用已有 ReaderHostView 完成接线；二选一，以最小改动且不破坏位置/翻页契约为准，禁止另建第三套 Reader。表格实际呈现列/单元格，本地图片 Ready 分支实际绘制 bitmap。
- 验收：从 App 阅读路由打开样本，H1–H6、粗斜体、删除线、任务列表、引用、行内代码有实际样式；表格窄屏横向可读；代码原文复制保持一致；PNG/JPEG 真正显示；远程图片零自动网络加载。
- 交互：链接/复制/横向滚动优先于翻页；字体和宽度变化保持位置；图片加载完成、旋转、换文档、复用条目无错图或已回收 bitmap 使用。
- 证据：设备测试调用生产创建方式与真实视图；附可辨认的示例截图及自动断言，不以 createForJvmTests 的字符串输出证明富文本。
- 停止：不做语法高亮、字体包、表格 CARD/WRAP、网络图片。

## R2-04 — 扫描提交原子性与进度保留

- 优先级：P1；前置：R2-00；对应 REQ-0001、0003，发现 F05。
- 文件范围：LibraryScanner、Room DAO/数据库边界、storage 测试。
- 实施：扫描阶段与提交阶段分离；完整提交使用真实事务，取消/错误回滚至旧索引。文档元数据更新不得通过父行替换删除位置。审计更新、删除、移除 Library 的并发关系。
- 必须使用真实 Room 复现：保存位置后刷新修改过的文档；提交第 N 条时取消/抛错；删除阶段失败；刷新与移除库交错。
- 验收：异常/取消后完整比较旧 Document/ReadingPosition/lastScannedAt；成功刷新保留可供回退的位置记录，真实删除才清对应记录。源文件 checksum 不变。
- 规模边界：当前 500 文档/5000 条目硬上限必须测量并记录处理结论，禁止通过上限掩盖 O(N²) 去重。此项不要求建设大规模索引平台。
- 回滚：优先不改 schema；必须改 schema 时提交 Migration 与已有数据库升级验证。

## R2-05 — 历史位置指纹与可恢复错误

- 优先级：P1；前置：R2-01、R2-02、R2-04；对应 REQ-0001、0003，发现 F06。
- 文件范围：ReaderWiring、ReaderViewModel、Repository/位置读取接口、授权恢复入口。
- 实施：读取位置保存时的真实 fingerprint，和当前文档指纹分开；明确刷新/重开后的缓存失效。存储异常在已有边界转为 ReaderFailure；失权进入重新授权，文件消失进入移除/重试。
- 验收：保存 → 外部修改 → 手动刷新 → 重开走 anchor/progress 回退；null 指纹不可复用旧内容；进程重建/旋转/退出位置有效。真实授权失效后重新选择同树，保留 Library 身份与历史进度并恢复阅读。
- 测试：用实际 storage 异常类型贯穿生产 wiring，不只用 FakeGateway 抛 SecurityException；最近阅读缺失/失权状态与 Reader 一致。
- 停止：不扩展跨库授权、云 provider 同步或 content hash 全库计算。

## R2-06 — 可取消且与真实渲染一致的文内搜索

- 优先级：P1；前置：R2-02、R2-03、R2-05；对应 REQ-0008，发现 F07/F01。
- 文件范围：DocumentSearch、BlockPositionMap、SearchHighlight、ReaderViewModel/Screen 的搜索绑定。
- 实施：搜索循环协作取消，避免无限量物化高密度匹配；如采用限额/分批，必须明确总数与结果完整性语义，不能静默少报。高亮坐标与真正显示的富文本一致。
- 验收：10 MB 重复字符查询/快速改查询/切文档可以取消，无旧高亮残留；搜索不到 Markdown 语法标记但能找到可见表格/代码文本；中日英/emoji、重复词与无匹配均可正确跳转。
- 停止：不引入 FTS、正则、全库搜索；不在输入时重解析全文。

## R2-07 — 真实页面回归与 E-Ink 验收

- 优先级：P1；前置：R2-03、R2-05、R2-06；对应全部 MVP REQ。
- 文件范围：app/src/androidTest、相关测试配置、测试/性能记录；仅验证，不顺带修功能。
- 增加双 flavor 的真实场景：添加测试目录 → 浏览 → MD/TXT → 字体/模式切换 → TOC/搜索/图片 → 退出恢复；覆盖旋转、失权、删除目标和点击区域仲裁。
- 大文件必须经过实际 App 生产 ReaderSession、Markwon 和页面；记录读取、解码、解析、首屏可读、取消耗时与内存，不能只测 parser 或把 settled PSS 当峰值。
- 验收：两个 connected app task 均执行非零用例、产生报告；运行 storage/markdown 的实际模块设备任务；匹配当前源码快照。不同层的用例数量分别报告。
- 实机：普通 Android 与可取得的 BOOX 设备按矩阵测试；缺失 6/7/10.3 寸类别维持 NOT_RUN，硬件残影未验证不得宣称完成 E-Ink 发布验收。
- 停止：若发现缺陷，记录复现和所属 R2 任务，不在验证任务中扩大实现范围。

## R2-08 — 状态、许可与 Alpha 候选报告

- 优先级：P2；前置：R2-07；对应 REQ-0010、0011，发现 F09。
- 文件范围：README、AGENTS、REQ 索引/状态、architecture、release/testing、APK/性能记录、CHANGELOG、验收报告。
- 更新为真实现状；删除“尚无工程”“已接通但没有生产调用”等错误描述；修正未签名 release、许可证待定、测试覆盖范围。已有 Accepted ADR 的决策变化通过新 ADR 替代，不改写决策历史。
- 验收：每条 AC 映射到用例/命令/人工记录；PASS、FAIL、NOT_RUN 分列；没有测试的任务不算通过。性能表格标明实际测量路径、环境、样本和源码标识。
- 重新生成双 release 候选与体积报告，确认测试样本不入包、权限与离线边界未扩张。
- 项目许可证、正式 ID、签名与发布渠道依然由项目所有者决定；本任务不自动签名、提交、推送、发布。
- 停止：交付明确说明“可通过的部分”和“仍阻塞发布的部分”；无阻塞且证据齐全的 REQ 才标 DONE。
