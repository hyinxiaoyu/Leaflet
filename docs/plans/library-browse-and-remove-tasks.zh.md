## 顺序

LT-1 与 LT-4 互不依赖。LT-2 等待 LT-1。LT-3 等待 LT-2，而且只有它可以为目录增加元数据。

| ID | 任务 | 依赖 | 交付 |
| --- | --- | --- | --- |
| LT-1 | 当前层排序 | 无 | 一个经过测试的函数：给定目录前缀，先返回子目录，再按名称返回文件 |
| LT-2 | 逐层浏览 | LT-1 | `LibraryBrowseScreen` 只显示一层，可进入目录并返回 |
| LT-3 | 空目录 | LT-2 | 目录元数据，使没有已索引文档的文件夹也能出现 |
| LT-4 | 长按移除 | 无 | 资料库列表长按确认后调用 `removeLibrary` |

## LT-1 — 当前层排序

基于已经索引的文档做一个纯函数。输入是当前相对前缀和文档列表。输出是直接子目录，然后是直接子文件。

每一组内部先按大小写不敏感的名称排序，再用原始名称打破平局。目录名是 `relativePath` 的下一段。文件名是最后一段。不要按完整路径给整个资料库 (Library) 排序。

测试覆盖：根前缀和嵌套前缀、文件与目录并列、中文和大小写混合的名称、用原始名称打破的平局，以及当前层不显示更深层文件。不改 Room。不做界面。

纯函数和它的 JVM 测试通过后停止。不要打开浏览页。

## LT-2 — 逐层浏览

替换平铺的 `groupedEntries` 列表。界面显示当前前缀对应的 LT-1 行。点目录就设置该前缀。在根层返回会离开资料库。在根层之下返回则向上一段。点文件仍按文档 id 打开阅读页。

空状态、刷新、取消和失败文案保持不变。两个风味 (flavor) 共用这个界面。E-Ink 保持静态，不加新动画。如果工程里已经有对应的测试骨架，就补一个针对前缀切换的界面测试或 JVM 测试；不要新增测试框架。

当前层按「目录然后文件」的顺序显示，并且导航能回到上一层之后停止。本任务不保存空目录。

## LT-3 — 空目录

在现有扫描里把目录记成元数据：只有相对路径，不读文件正文，不复制原文。一个没有 Markdown 或 TXT 后代的目录仍然显示为目录行，并使用 LT-2 的空占位。

保留现有的遍历上界、取消行为，以及失败扫描不丢弃上次索引的规则。原始字节保持不变。

交付内容：`directories` 表（数据库版本 2，`MIGRATION_1_2`）、扫描器的纯路径行，以及浏览层与文档推导父路径的合并。

一次成功扫描能留下空目录，并在其父层显示之后停止。不要把本任务和 LT-1 或 LT-2 放在同一次改动里。

## LT-4 — 长按移除

在资料库列表上长按一行。确认文案说明只移除本地引用和索引。确认后调用 `LibraryRepository.removeLibrary`。取消则所有行都留在原地。

用现有仓储测试或一个新的界面测试证明：该库的文档、阅读位置和最近阅读记录都消失；共用授权保留；未共用授权释放；原始字节不变。E-Ink 使用静态确认，不要求水波纹。

确认移除后列表更新即停止。不要删除 SAF 原文。不要在浏览里移除子目录。

## 交接

每个任务报告改了哪些文件、跑了什么命令、什么没跑。完成一项不会自动开始下一项。LT-1～LT-4 均已达到停止条件；REQ-0001 的 A1 与 A2 不再是 `DRAFT`。
