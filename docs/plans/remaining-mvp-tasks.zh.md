R3-05～08 是后续软件验收工作；R3-09/10 的设备安排和所有者决策可以提前准备，实际发布取决于验收结果。

角色分工：项目经理/架构负责人维护任务边界、审计证据和验收；执行 agent 补测试并修复本任务确认的缺陷。验证发现跨模块契约问题时先说明影响，不顺带重构。

## 每个工作包的统一交接

1. 输入：对应 REQ、架构/ADR、上表任务范围、前置交付与源码标识。
2. 先验证现有行为；已满足的条件复用有效证据，不重复实现。
3. 若发现缺陷，记录复现→失败测试→最小修复→回归；不通过降低 AC、删断言或扩大 timeout 结案。
4. 输出：变更文件、真实命令/用例数量、设备与样本、PASS/FAIL/NOT_RUN、残余风险。
5. 独立验收前状态为“待验收”，不由执行 agent 的自述替代最终关闭。
6. 到工作包停止条件即结束，不自动领取下一包，不自动提交或发布。

本轮规划不运行构建、不修改实现。R3 编号在本文件中统一，以本版细分取代聊天中先前的四项粗分。
