# REQ-0008 — 当前文档内搜索

[English](REQ-0008-in-document-search.md) | 中文

Status: READY
Priority: P0
Milestone: M1

## 问题

AI 资料多为数千行以上长文档，用户需要快速定位关键词（如某个参数名、错误码）。没有文内搜索时只能手动滚动翻页，在 E-Ink 上尤其痛苦。MVP 不做全库 FTS（`docs/archive/init.md` §25 可延后），但当前文档搜索是 MVP 必做（§26"文内搜索"），必须先交付且行为正确。


来源：`docs/archive/init.md` §25（搜索）、§26（MVP 必做含文内搜索）；`docs/plans/M0-M1-implementation-plan.md` T11。

## 用户故事

作为需要在长文档中查找关键信息的读者，我希望在当前文档输入关键词、查看匹配数量并在匹配间跳转，以便无需手动翻遍全文即可定位内容。

## 范围

包含：

- 当前已加载文档内的字面量（literal）搜索：输入查询串，返回匹配计数，支持上一个/下一个跳转，当前匹配高亮。
- Markdown 按可见文本搜索：不把 Markdown 语法标记（如 `#`、`*`、`[]()` 符号）当正文参与匹配；代码块与表格内的可见文本参与搜索。
- 使用解析/渲染位置映射定位匹配：经 block → 条目 → 可见行/偏移的映射跳转，禁止直接把源码 offset 当屏幕坐标。
- 搜索任务可取消：输入变化或切文档时旧任务取消，过期结果不得覆盖新结果。
- 大文件/纯文本降级模式下有明确搜索行为（至少纯文本全量字面量搜索可用，见 FR-9）。
- 无匹配、有匹配、切文档等状态有明确 UI 反馈。

## 非目标

明确不包含：

- 正则表达式、高级查询语法（AND/OR/通配符/大小写开关如超出字面量范畴，均不做）。
- 全库搜索、后台全库索引、Room FTS（`docs/archive/init.md` §25 明确可延后；Repository 层仅预留能力）。
- 搜索结果跨文档聚合、搜索历史持久化。
- 替换功能（阅读器只读）。
- 每次输入时重新解析全文（T11 验收明确禁止）。

## 用户体验

- 阅读器菜单或工具栏提供搜索入口，点击展开搜索条：输入框、匹配计数（如 `3/12`）、上一个/下一个按钮、关闭按钮。
- 输入后显示匹配总数；无匹配时显示明确空态（如"无匹配"），不静默无反应。
- 当前匹配以区别于其他匹配的高亮样式标示；跳转时滚动到该匹配可见（E-Ink 为 instant 滚动，无 smooth 动画）。
- 关闭搜索或切换文档时清除高亮与旧状态。
- 查询为空时不执行搜索，不显示错误。

## 功能需求

- FR-1：搜索框输入查询串后，Reader 对当前已加载文档执行字面量匹配，返回匹配总数并支持前后跳转。
- FR-2：匹配按渲染可见文本计算：标题、正文、列表、引用、代码块文本、表格单元格文本参与；Markdown 语法标记本身不参与匹配。
- FR-3：定位经解析/渲染位置映射（block index + 块内可见偏移 → RecyclerView 条目 → 行），源码 offset 仅允许作为解析侧输入，禁止直接用作滚动像素或条目坐标。
- FR-4：搜索在后台可取消任务中执行；新查询或文档切换取消旧任务；旧任务的过期结果到达时丢弃，不得覆盖当前展示。
- FR-5：切换文档时清除上一文档的查询串、计数、高亮与任务状态。
- FR-6：查询变化时复用已解析文档结构增量匹配，不得触发全文重新解析。
- FR-7：搜索栏显示当前匹配序号与总数；无匹配显示零状态；空查询不触发搜索。
- FR-8：TXT 文档同样支持字面量搜索（全文即为可见文本）。
- FR-9：纯文本降级条目（如超大单块降级）内的文本仍可被搜索到并可跳转；若某降级策略确实不可定位，实现时必须在 UI/文档中声明并经 T11 验收，不得静默跳过。

## 验收标准

- AC-1：给定含 5 处分散匹配的中文样本，输入关键词显示总数 5，前后跳转顺序遍历全部 5 处且序号正确。
- AC-2：给定含 Markdown 标记的样本（如 `# 标题`、`**加粗**`、`[文字](url)`），搜索标记字符（如输入 `**` 或 `](`）不命中正文；搜索可见词（如`标题`）命中且计数正确。
- AC-3：给定代码块与表格含关键词的样本，搜索命中其中的可见文本并可跳转到对应条目。
- AC-4：快速连续输入（如 200ms 内输入 5 个字符）后，最终只展示最后一次查询的结果；profiling/日志证明旧任务被取消且无过期覆盖。
- AC-5：打开文档 A 搜索后切换到文档 B，B 的搜索状态为初始空态，A 的高亮不残留。
- AC-6：给定无匹配查询，显示无匹配状态，不 crash、不跳转。
- AC-7：给定含 emoji、日文、重复匹配的样本，计数与跳转正确；跨 block 的查询词（如横跨两段的长串）按"不跨块匹配"规则处理并有单测锁定该规则。
- AC-8：10 MB 样本或降级模式下执行搜索：不 ANR、不 OOM，允许 loading 状态，结果行为与 FR-9 声明一致。

## 边界情况

- 空查询、纯空白查询：不搜索，保持现状。
- 查询含 emoji、中文、日文、大小写混合：按字面量精确匹配（大小写规则见 Open Questions，未定则实现时锁定并记录）。
- 文档为空：搜索显示无匹配，不 crash。
- 重复标题/重复匹配密集段：跳转顺序按文档顺序稳定。
- 后台搜索进行中退出阅读器：任务取消并释放资源，不泄漏、不回调已销毁 UI。
- 超大单块降级条目内的匹配：可达性以 FR-9 声明为准。

## E-Ink 考量

- 跳转滚动为 instant，禁用 smoothScroll；高亮为静态高对比色块，无闪烁/呼吸动画。
- 搜索输入过程不触发全屏刷新风暴；结果呈现依赖系统刷新，残影结论以实机矩阵为准。
- 键盘弹出/收起不导致阅读位置丢失（与 REQ-0005 位置策略协同）。

## Standard Android 考量

- 允许搜索条出现/消失的轻微 transition，但不得依赖动画传达搜索结果。
- 允许使用系统键盘联想，但查询串仍按字面量原文匹配。

## 性能考量

- 搜索不得在每次输入时重新解析全文（T11 验收）；匹配基于已解析可见文本索引或增量扫描。
- 大文档搜索可取消、可 loading；禁止 O(N²) 实现（`docs/archive/init.md` §50）。
- 性能数字（搜索延迟阈值）不由本 REQ 编造，待 REQ-0011 基线建立后引用。

## 存储与数据影响

- 不持久化搜索查询与结果；不建全库索引；不写原文。
- 内存中的可见文本索引随文档关闭释放；取消任务释放相关资源。
- Room FTS 预留仅为 schema/Repository 层兼容性说明，不在本 REQ 建表。

## 测试计划

- 单测：字面量匹配计数（中/日/emoji/重复/无匹配）；Markdown 标记不参匹配；跨块不匹配规则锁定；过期结果丢弃逻辑。
- 样本：`testdata/markdown/` 的 `long.md`、`chinese.md`、`japanese.md`、`unicode.md`、`code.md`、`tables.md`、`malformed.md`（`docs/archive/init.md` §48）；10 MB 样本验证 AC-8。
- UI/instrumented：AC-1 跳转遍历、AC-5 切文档清除、AC-4 快速输入取消行为。
- E-Ink 实机：搜索跳转残影观察记入 `eink-test-matrix.md`；无设备标 NOT_RUN。

## 依赖

- REQ-0002（基础 Reader 与分块渲染：搜索依附的文档结构）。
- REQ-0003（阅读位置：跳转目标的块/偏移语义）。
- REQ-0005/0006（翻页仲裁、TOC 跳转：共享定位映射）。

## 待确认问题

- 大小写敏感性默认值：T11 冻结为**默认区分大小写**（字面量 `String.indexOf` 语义；`ErrorCode`/`errorcode`/`ERRORCODE` 互不命中，单测锁定；搜索框 hint 注明“区分大小写”）。如需不敏感归一化另立 REQ。
- 是否支持"仅当前章节"限定搜索：未验证，默认不做，如需则另立 REQ。
- 降级条目不可定位时的确切 UI 文案：T11 结论——超大单块降级为有界纯文本分块（`PLAIN_FALLBACK`），文本同样可搜可跳（`DocumentSearchVisibilityTest.degradedFallbackChunksAreSearchable`）；无“不可定位”降级，无额外文案。
- 搜索延迟回归阈值：待 REQ-0011 性能基线建立后引用，不在本 REQ 预设数字。
