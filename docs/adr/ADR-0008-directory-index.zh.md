# ADR-0008 — 为浏览索引目录元数据

[English](ADR-0008-directory-index.md) | 中文

状态：Accepted（已接受）
日期：2026-09-28

## 背景

REQ-0001 A1 要求资料库 (Library) 浏览保留目录结构，并且即使某个文件夹里没有任何已索引的 Markdown 或 TXT 文档也要显示它。版本 1 的索引只存文档行，浏览层只能从 `Document.relativePath` 的父路径片段推导文件夹。这种推导无法表示没有已索引后代的文件夹：空文件夹，或只含不受支持文件的文件夹，会直接消失。[资料库浏览与移除](../plans/library-browse-and-remove-tasks.zh.md) 里的 LT-3 是被授权保存目录元数据的后续任务，它不得读取文件正文，也不得复制原文（ADR-0001）。

约束：

- 原始文件是唯一事实来源；数据库只存辅助元数据（ADR-0001）。
- 失败、取消或超限的扫描必须零提交，并保留上一次的索引（REQ-0001 FR-5/FR-6）。
- 扫描只做元数据，并受现有「访问 5000 条目」上界约束。
- 已有安装必须无损升级，不丢资料库、文档、阅读位置和最近阅读记录。

## 决定

1. 新增纯路径的 `directories` 表（`libraryId` + `relativePath` 复合主键，外键指向 `libraries` 并 `ON DELETE CASCADE`），并带一个经过测试的 `MIGRATION_1_2` 把数据库升到版本 2。该迁移是纯增量的，只建一张空表，不修改任何既有行。
2. 扫描时为遍历到的每个子目录写一行，无论其中是否有受支持文档。遍历本来就会枚举这些条目，因此不增加额外遍历，也不打开任何数据流。
3. 目录行与文档行在同一个 Room 事务里提交，并遵守同一套规则：失败、取消或超限的遍历零提交；子树证据不完整的遍历不删除任何行。
4. 浏览层由「已索引目录行」与「从文档路径推导出的父路径片段」的并集构成。推导保留为兜底，这样 LT-3 之前写入的索引无需强制重扫也能继续浏览。
5. 移除资料库时，目录行通过清文档和阅读位置的同一个 Room 级联被清除。移除过程绝不触碰源文件夹。

## 考虑过的替代方案

- **只从文档路径推导文件夹（不改 schema）：** 保持版本 1、无需迁移，但无法表示没有任何已索引文档的文件夹，而这正是 A1 明确要求的。已否决。
- **在 `documents` 里用哨兵扩展名或 `isDirectory` 标记目录行：** 省掉新表，但会把非文档行混进所有文档查询（计数、阅读页路由、最近阅读），削弱文档不变量。已否决。
- **打开浏览页时按需枚举文件夹：** 无需持久化，但让界面依赖每一层的实时 provider 查询，在扫描器之外多出第二条枚举路径，并失去浏览的离线/陈旧索引行为。已否决。
- **除路径外还存文件计数、mtime 或预览：** 超出需求所需，且需要更多失效逻辑。已否决，只存路径。

## 影响

- 数据库版本 2；`core/storage/schemas/**/1.json` 与 `2.json` 是经过评审的基线，`DirectoryMigrationTest` 会打开 v1 数据库、执行迁移，并断言每一类代表性行（包括未知的未来位置版本）都保留下来。
- 每个访问到的文件夹一行，受现有遍历上界约束。目录行不增加文件正文存储，也不访问网络或原始文件。
- 扫描器的提交现在会原子地写两张表；目录写入失败会回滚整次索引更新。
- 按子目录移除、按时间/大小排序文件夹、全库 FTS 仍不在范围内。

## 后续

- 文件夹存在但无法枚举时的真机 provider 行为，在 T13 基线之前仍未验证；这类遍历会记录条目错误并抑制清理。
- 如果 M4 加入全库搜索或更大的浏览模型，再评估目录行是否需要额外列；不要提前添加。
- Room 2.8.5 + KSP 的 schema 导出限制记录在 `core/storage/build.gradle.kts`；重新生成 schema 使用文档化的按需开关 `-Proom.schemaExport=true`。
